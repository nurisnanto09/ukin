Materi & Simulasi Terpadu Pseudocode

Pelajari struktur resmi pseudocode sebagai satu kesatuan dokumen yang utuh. Setiap bagian—Judul, Deklarasi, hingga Algoritma—dapat kamu bedah dan uji langsung melalui simulasi interaktif di bawah!

📄 Struktur Utuh Notasi Algoritma

Satu Kesatuan Pseudocode: 3 Bagian yang Wajib Ada

Program pseudocode bukan kumpulan baris terpisah, melainkan sebuah dokumen algoritma utuh yang tersusun rapi dari 3 pilar: 1. Judul Program → 2. Deklarasi (Kamus Variabel) → 3. Algoritma (Instruksi Proses). Klik tombol simulasi pada setiap bagian untuk mempelajari aturan dan mencoba simulasinya!

Peta Struktur:
Judul → Deklarasi → Algoritma

LEMBAR_PROGRAM: Kasir_Toko_Sederhana

Total: 14 Baris Eksekusi
BAGIAN 1 JUDUL PROGRAM (HEADER) • Menentukan nama & spesifikasi tujuan program
1. Program Hitung_Total_Bayar
2. { Menghitung total belanjaan siswa berdasarkan jumlah barang dan tarif harga satuan }
💡 Kaidah Baku: Nama program wajib 1 kesatuan (tanpa spasi), deskripsi singkat diapit tanda kurung kurawal { ... } sebagai komentar yang tidak dieksekusi.
BAGIAN 2 DEKLARASI (KAMUS VARIABEL & TIPE DATA) • Menyiapkan wadah penyimpanan & menentukan jenis data
3. DEKLARASI:
4. nama_pembeli : string { Wadah teks nama berpetik }
5. jumlah_barang : integer { Wadah bilangan bulat utuh }
6. harga_satuan : real { Wadah angka desimal uang }
7. total_bayar : real { Wadah penampung hasil perhitungan }
💡 Kaidah Baku: Komputer memesan toples penyimpanan. Tipe data (string, integer, real) berperan sebagai penjaga pintu keamanan yang memastikan hanya data berizin yang boleh masuk.
BAGIAN 3 ALGORITMA (LANGKAH EKSEKUSI PROSES) • Urutan instruksi operasional yang dijalankan komputer
8. ALGORITMA:
9. read(nama_pembeli)
10. read(jumlah_barang)
11. read(harga_satuan)
12. total_bayar <- jumlah_barang * harga_satuan
13. write("Nama Pelanggan : ", nama_pembeli)
14. write("Total Tagihan Rp : ", total_bayar)
💡 Kaidah Baku: Instruksi berjalan terurut dari baris atas ke bawah: Membaca input (read), menugaskan/menimpa nilai baru (<-), dan mencetak keluaran (write).
1️⃣ Peran Bagian Judul

Memberi identitas dan tujuan fungsi program. Komputer dan sesama programmer tahu apa yang sedang diselesaikan algoritma.

2️⃣ Peran Bagian Deklarasi

Mempersiapkan kotak toples penyimpanan (variabel) dan menentukan tipe data penjaganya sebelum nilai mulai diproses.

3️⃣ Peran Bagian Algoritma

Instruksi kerja nyata: membaca input, melakukan kalkulasi matematika, dan mencetak hasil keluaran (output).

Bagian 1: Judul (Header)

Identitas & Spesifikasi Algoritma

Bagian Judul berfungsi memberikan nama pengenal unik untuk algoritma serta menjelaskan secara ringkas apa tujuan program tersebut dibuat.

Format Standar:
PROGRAM Nama_Algoritma
{ Penjelasan ringkas apa yang dikerjakan program }
Aturan Baku Menuliskan Judul:
  • 🚫 Tidak boleh ada spasi: Sama seperti variabel, komputer bingung jika ada spasi di tengah nama. Gunakan garis bawah (_) atau camelCase.
  • ✔ Wajib diawali huruf alfabet: Contoh: Hitung_Luas (Benar), 1Hitung (Salah karena dikira angka matematika).
  • 🚫 Dilarang simbol operasi: Jangan memakai minus (-), kali (*), atau tanda seru karena dikira rumus aritmatika.
  • 📝 Deskripsi dalam kurung kurawal: Penjelasan spesifikasi diapit { ... } sebagai komentar dokumentasi.

Bagian 3: Algoritma (Aksi & Alur Eksekusi)

Jantung Eksekusi: Komputer Menjalankan Instruksi Baris Demi Baris

Bagian Algoritma memuat serangkaian perintah operasional nyata. Komputer mengeksekusi instruksi secara runtun dari atas ke bawah: Membaca input, melakukan kalkulasi matematika, membuat keputusan IF-ELSE, dan menampilkan hasil keluaran (output).

📥 1. read(...) / INPUT

Membaca masukan dari pengguna dan memasukkannya ke variabel.

⚡ 2. Penugasan (<-)

Menghitung ekspresi kanan, lalu menimpa hasilnya ke variabel kiri.

🔀 3. IF - THEN - ELSE

Memilih cabang instruksi berdasarkan kondisi benar/salah.

📤 4. write(...) / OUTPUT

Mencetak hasil komputasi ke monitor layar pengguna.

💡 Tahap 1: Konsep & Apersepsi (Mengapa Harus Pseudocode?)
🧭 Pertanyaan Mendasar Informatika

Mengapa Harus Pseudocode?

Sering muncul pertanyaan: "Kenapa kita tidak langsung koding? Kenapa tidak pakai bahasa sehari-hari saja?" Di modul ini, semua pertanyaan itu terjawab secara tuntas: mulai dari simulasi kasus nyata saat narasi ambigu membuat toko tekor jutaan rupiah, konsep dasar dan definisi pseudocode, hingga kerangka berpikir logis IPO!

🎭 Studi Kasus: Mengapa Bahasa Manusia Tidak Cukup

Bencana Narasi Ambigu: "Klien Salah Berucap, Programmer Salah Bikin!"

Komputer tidak memiliki akal sehat atau intuisi manusia. Jika instruksi diberikan dengan bahasa sehari-hari yang ambigu (bisa bermakna ganda), programmer dan komputer akan menerjemahkannya secara harfiah dan menciptakan program yang salah fatal!

Mas Ari (Programmer Komputer) Menerjemahkan ke Baris Kode:
💭 Pikiran & Kebingungan Programmer:

"Waduh... 'laptop ATAU printer yang bawa VIP'? Apakah:
(1) Siapa pun beli laptop langsung diskon 50% (tanpa butuh kartu), atau beli printer yang ada VIP?
(2) Atau dua-duanya wajib bawa VIP? Karena kalimatnya digabung, saya ketik opsi pertama saja deh!"

💥 Akibatnya: Programmer mengetik kode dengan interpretasi yang SALAH!
Interpretasi A (Program yang Terlanjur Salah):
Bencana 💸
// Kurung logika memisahkan laptop sendiri:
IF (beli_laptop) OR (beli_printer AND punya_kartu_vip) THEN
diskon <- total_harga * 0.50
ENDIF
❌ Dampak Nyata di Kasir:

Pelanggan umum yang TIDAK MEMILIKI KARTU VIP membeli laptop Rp 10.000.000 langsung dipotong diskon 50% menjadi Rp 5.000.000! Toko Pak Budi rugi puluhan juta rupiah dalam 1 hari!

Interpretasi B (Maksud Asli via Pseudocode Baku):
Solusi Tepat 🛡️
// Tanda kurung tegas: Wajib punya VIP!
IF (beli_laptop OR beli_printer) AND punya_kartu_vip THEN
diskon <- total_harga * 0.50
ENDIF
✔ Hasil yang Benar:

Hanya pembeli yang memegang kartu VIP yang berhak mendapatkan diskon 50%, baik mereka membeli laptop maupun printer. Toko aman dan untung!

✨ Kesimpulan Penting Mengapa Kita Butuh Pseudocode:
Bahasa Alami (Sehari-Hari):

Penuh ambiguitas, memiliki tafsir ganda, tergantung intonasi dan asumsi, sehingga sangat berbahaya jika langsung diimplementasikan menjadi sistem komputer.

Pseudocode (Kode Semu Baku):

Memiliki struktur baku, tanda kurung kondisi yang tegas, alur baris terurut (sekuensial), sehingga tidak ada celah multitafsir antara manusia dan komputer.

📖

Apa Itu Pseudocode?

Bukan Kode Nyata, Melainkan Jembatan Logika

Pseudocode (secara harfiah berarti kode semu) adalah cara penulisan algoritma yang menyerupai bahasa pemrograman tingkat tinggi (seperti Pascal, C++, atau Python), namun ditulis menggunakan kata-kata sederhana yang mudah dibaca oleh manusia.

Kelebihan Pseudocode:
  • Struktur rapi & teratur (3 bagian baku)
  • Sangat mudah diterjemahkan ke bahasa apa pun
  • Lebih presisi untuk perhitungan matematis
Fungsi Utama:
  • Merancang logika sebelum mengetik kode nyata
  • Dokumentasi algoritma antar programmer
  • Media uji langkah berpikir komputasional
🎯

Kerangka IPO

Tiga Langkah Berpikir Komputasional

1. INPUT (Masukan)

Data apa yang diperlukan dari pengguna? (misal: panjang, lebar).

2. PROCESS (Proses)

Rumus atau keputusan apa yang dihitung? (misal: luas <- p * l).

3. OUTPUT (Keluaran)

Informasi apa yang dicetak ke layar? (misal: cetak nilai luas).

Langkah Berikutnya: Cetak Biru Notasi
